# 본보고서 작성 톤 및 bullet 위계 규칙

작성일: 2026-09-21
적용 범위: `90.최종보고서/` 하위 본보고서 md 초안 전체
레퍼런스:
* JRI 정책연구 2024-18 「에너지 대전환 시나리오에 따른 지역경제 효과분석」(강영준·윤형석, 2024)

## 규칙

* 헤딩 위계는 장-절-소절(`#`/`##`/`###`)까지만 쓰고 그보다 깊은 단계는 만들지 않음
  * 번호는 직접 달지 않고 템플릿이 자동으로 매김 (「헤딩 간격」 섹션 참조)
* 평문(prose 단락)은 일절 쓰지 않음. 모든 본문은 헤딩(`#`/`##`) 아니면 bullet(`*`)으로만 구성함
  * 헤딩과 bullet 사이, 또는 bullet 그룹 사이에 산문 문단을 끼워 넣지 않음
  * 한 줄짜리 설명·전환 문장도 평문으로 두지 말고 bullet로 표현함
  * 본문 콘텐츠는 2단 bullet 위계로만 전개함 (예외: 표·수식·인용 블록)
* 종결어미는 음슴체 (예: "검토함", "전망됨", "기대됨", "한계가 뚜렷함"). 다체("~한다", "~이다")나 합쇼체("~합니다") 모두 금지.
* 음슴체 끝 마침표는 쓰지 않음
* bullet은 **2단계 위계로만** 표현. 메인 bullet과 부연 bullet 두 단계까지만 사용함. 3단 이상 들여쓰기는 금지.
  * 마커는 `*`로 통일.
  * 메인 bullet들만 순서대로 읽어도 스토리·논리가 완결되어야 하고, 부연 bullet은 설명·예시·근거가 필요할 때만 씀.
* 모든 bullet은 **문장형**으로 작성함 (명사형 어구·키워드 나열 금지)
  * 각 bullet은 서술어를 갖춘 완결 문장이어야 하며, 음슴체 종결 규칙과 결합되어 동사·형용사 음슴체로 끝남
  * 명사형 단독 나열 금지 예: "재정 효과 분석" (불가) → "재정 효과를 분석함" (가능)
  * 키워드·구문 나열 금지 예: "한계: 자료 부족, 시계열 단절" (불가) → "자료 부족과 시계열 단절로 한계가 뚜렷함" (가능)
  * 메인 bullet과 부연 bullet 모두 동일 규칙 적용
  * 예외: 표·그림 캡션(명사형 종결), 목차 항목, 章·節 제목
* 각 장은 章 제목 바로 아래에 「장 도입 블록」을 배치함
  * 도입 블록은 본 장이 다루는 범위·접근 방식·주요 자료원·결과의 윤곽을 독자에게 사전 안내함
  * 위치는 章 제목(`# …`) 바로 아래, 첫 節 제목(`## …`)보다 위
  * 도입 블록도 본 규칙에 따라 2단 bullet으로 표현함 (일반 산문 단락 금지)
* 깊은 헤딩(`####`)·bold strong 같은 markdown 장식은 최소화함. 절 번호는 직접 쓰지 않고 템플릿이 `1-1`, `1-2` 형식으로 자동 부여함 (JRI 정책연구 표준).
* 표·수식·인용은 그대로 사용. 표 캡션은 `<표 Ⅰ-1>` 형식, 그림 캡션은 `[그림 Ⅰ-1]` 형식. 캡션 본문은 명사형으로 끝남 ("〜 전망", "〜 현황", "〜 효과").
* 표·그림 제시 시 본문에 해석·설명이 반드시 동반되어야 함
  * 표/그림만 단독 제시하고 끝내는 것 금지
  * 본문에서 핵심 발견·시사점·근거 활용 방식을 명시
  * 권장 위치: 표/그림 직전 도입(예: "…는 〈표 Ⅱ-1〉과 같음") 또는 직후 해석(예: "〈표 Ⅱ-1〉에서 보듯이 …")
* 모든 표·그림은 자료 출처를 기재함이 원칙
  * 자체 산출(원자료를 직접 가공·계산)인 경우 출처 기재 생략 가능
  * 표기 형식: 표/그림 하단에 `자료) 저자(연도)` 또는 `자료) 기관명, 자료명(연도)` 등
  * 상세 형식은 `citation/latest.md` 「표/그림 하단 출처 인용」 규칙 적용
* 기간·범위 표기는 ASCII 물결표(`~`) 사용 금지
  * 마크다운 파서가 취소선(`~text~`)으로 해석할 위험 있음
  * 전각 물결표 `〜` (U+301C) 사용
  * 예: "2020〜2024년", "1〜2개", "기준연도〜목표연도"
* 금액 단위는 맥락에 따라 선택
  * 직관적 가독성이 우선될 때: 만 원, 억 원 사용 (예: "예산 5,500만 원", "총사업비 100억 원")
  * 재정·회계적 정확성이 우선될 때: 천 원, 백만 원 사용 (예: "예산 55,000천 원", "총사업비 10,000백만 원")
  * 영문 약어 `M`, `k`는 전문 영역(기술·금융 등)에서만 사용

## 서술 톤 (표현 수위)

* 본 절은 bullet의 구조(위계·음슴체·문장형)가 아니라 문장 내 표현 수위를 규정함
  * 같은 사실도 과도하게 단정하거나 명사구로 압축하면 보고서 격이 떨어지고 딱딱하게 읽힘
  * 본 보고서는 연구원이 발주처(도청 등)에 권고·자문 성격으로 제출하는 문서이므로, 단정이 아니라 진단·제안·선택지를 제시하는 톤을 기본으로 함
* 단정 완화 — 단정적 부정·확언을 신중한 표현으로 씀
  * 과도한 부사("완전히", "전혀", "매우", "반드시")를 덜어냄
  * 예: "정성지표가 완전히 부재함" → "정성지표가 부재함"
  * 예: "왜곡이 발생함" → "고평가될 소지가 있음"
  * 예: "포착하지 못함" → "충분히 포착하지 못할 가능성이 높음"
  * 예: "측정 방법이 미정 상태임" → "측정 방법이 명확하게 정의되지 못한 상태임"
  * 정도·가능성 표현(소지·가능성·여지·우려·측면)으로 단정의 강도를 낮춤
* 동사 겸손화 — 연구자(본 연구·우리)가 주어인 행위 동사는 권고 성격에 맞춰 낮춤
  * 예: "통합 평가체계를 설계함 / 완성함 / 구축함 / 명확화함" → "제안함 / 제시함 / 보완 방향을 제시함 / 구체적으로 제안함"
  * 강한 당위("〜해야 함")는 "〜하는 것이 바람직함 / 〜을 권고함"으로 완화함
  * 단, 제3자(타 기관·타 지역)가 실제로 한 일은 원래 동사(운영함·수립함·도입함)를 유지함 — 겸손화는 연구자 행위에만 적용함
* 시제 — 연구가 수행·제안한 것은 과거형(`〜하였음` / `〜제안함`), 지향·의도는 `〜고자 함`으로 씀
  * 현재형 단정("분석함", "비교 분석함")만 반복하면 매뉴얼처럼 읽힘
  * 진단된 현 상태("편중되어 있음", "부재함")는 현재형을 유지해도 무방함
* 연결·맥락 보강 — 토막난 명사구 bullet에 연결어와 짧은 맥락을 더해 완결 문장으로 씀
  * 연결어 예: "우선 / 또한 / 이때 / 이로 인해 / 따라서 / 이를 통해"
  * 열거는 "첫째·둘째" 또는 "우선·다음으로·마지막으로"로 순서를 드러냄
  * 단, 연결·맥락 보강이 새로운 사실·수치·주장 추가로 번지지 않도록 함 — 표현만 보강하고 내용은 그대로 둠
* 명칭·성격 명시 — 약식 명칭은 정식 명칭으로, 수치는 성격을 함께 밝힘
  * 예: "제주 지표체계" → "제주 지속가능발전 지표체계"
  * 예: "325개 정량지표" → "325개 사업별 정량지표"
* 내부·기술 표기 제거 — 작성 과정에서 쓴 내부 표기는 본문에서 덜어냄
  * 코드·데이터 경로(`02.data/...` 등), "도출된 / 추출된" 같은 작업 흔적 표현
  * 단, "자료)" 출처 줄에 들어가는 자료 경로·출처는 인용이므로 유지함
* 위 규칙은 표·캡션·인용문에는 적용하지 않음 (표 셀·캡션·외부 인용 원문은 톤 교정 대상 아님)

## 헤딩 간격 (줄바꿈)

* 헤딩 위 여백은 변환기가 자동으로 넣으므로, 직접 빈 줄로 여백을 만들지 않음
* 평소에는 헤딩·문단을 빈 줄 없이 자연스럽게(빡빡하게) 이어서 작성함
  * 변환기가 헤딩 위에 그 헤딩 크기만큼 여백을 넣음
  * 부모 바로 아래 오는 헤딩(예: `#` 다음 바로 `##`, `##` 다음 바로 `###`)은 여백 없이 붙음
* 예외(override): 특정 헤딩을 평소보다 더 떼고 싶을 때만 그 헤딩 앞에 빈 줄 1개를 넣음
  * 이 경우 직속 자식 헤딩이라도 여백이 강제됨
* 빈 줄을 2개 이상 넣어도 효과는 1개와 동일함 (여백은 항상 1개, 헤딩 크기로 고정)
  * 간격 "크기"를 빈 줄 개수로 조절하려 하지 않음
* 위 규칙은 헤딩에만 적용됨. 문단·bullet 사이 빈 줄은 일반 마크다운 문법일 뿐 추가 여백을 만들지 않음
* 헤딩에 번호를 직접 달지 않음 — 템플릿이 자동으로 매김
  * 예: `## 부록 A:`, `### A-1`, `## 1.1`, `## 제2장` → 번호는 빼고 제목만 씀

## 내부 관리 표기 배제 (배포 대상 규정)

* 본 절은 배포 대상 본문(회람·제출·인쇄 대상 md·hwpx)에 들어가면 안 되는 편집·프로세스 표기를 열거함
  * 편집 편의로 md에 축적된 「우리만 아는 표기」가 배포본에 딸려나오면 발주부서·심의위원·외부 독자에게 부적절한 인상을 주고 문서 격이 떨어짐
  * 편집 관리용 정보는 별건 파일(예: `_편집메타/보고서명_편집메타_v0.X.md`)로 분리하거나 프로젝트 관리 노트에 별도 축적함
* 담당자 명찰·분업 표기를 배포본에서 삭제함
  * 헤딩 옆 대괄호 표기 (예: 「### 사업 개요 【현혜경】」) 삭제
  * 절 안 내부 메모 (예: 「이 절은 현 박사 담당임」·「아래는 조남운 측 초도 골격」) 삭제
* 문서 버전 참조를 배포본에서 삭제함
  * 부제·프론트매터의 「v0.X (집필 중 · W38 스냅샷 · 9/22 회람용)」 형식 표기 삭제
  * 본문 안 「v0.2에서 승격함」·「v0.4에서 확정할 예정」 같은 자기 참조 삭제 (필요하면 완료 시제로 재작성)
  * v0.1→v0.2→v0.3 개정 로그·「관련 문서」 리스트는 편집 메타로 분리
* 주차 표기(W37·W38·W40·W44 등)를 배포본에서 대체함
  * 배포 대상 눈에 맞는 시점 표기로 교체 (「9월 말까지」·「후속 단계에서」·「연구 종료 전에」 등)
* 자매·인접 프로젝트 코드·경로 참조를 일반화하거나 삭제함
  * 실명 코드 참조 (예: 「26P17 서귀포시 정책효과 인프라 재활용」·「compute_rio_single.py의 load_coef」) 삭제
  * 방법론 서술이 필요하면 일반화 (「자매 연구의 산업연관분석 인프라를 활용함」)
* 원내 이벤트·회람 참조를 배포본에서 삭제함
  * 「9/15 원내 연구지원통합회의 안건 등록 완료」·「9/22 원내 회람용」 등 삭제
* 별건 문서의 내부 경로 링크를 배포본에서 삭제함
  * 백틱 경로 (예: `` `30.data/03_분석/...` ``·`` `20.회의/20260828_.../..._통합정리_v1.0.md` ``) 삭제
  * 외부 독자가 열 수 없으므로 무의미하고 폴더 구조를 노출함
  * 인용 근거가 필요하면 서지 정보로 대체 (예: 「이종후 감독 인터뷰(2026-08-28)」)
* 단, 「자료)」 출처 줄의 자료 경로·발행처는 인용이므로 유지함
* 위 규정은 배포 대상 본문에만 적용됨. 편집 관리용 파일·작업 노트·인터뷰 통합정리 등에는 적용 X

## 적용 시 주의

* 챕터별 md(`01_서론.md` 〜 `08_결론.md`) 작성·수정 시 항상 본 규칙을 검사함.
* 장 도입 단락은 첫 절의 「개요」 항과 역할이 중복되지 않도록 함. 도입 단락은 장 전체 윤곽, 「개요」 항은 첫 절의 진입 설명에 한정.
* 메타 문서(목차안, 자료 매핑, 작업 계획)는 본문 prose 부분만 음슴체 적용. 목차 항목 자체(체언으로 끝나는 제목)는 톤 적용 대상이 아님.
* 외부 인용문(수행계획서, 회의록 등)은 출처 명시 후 원문 톤 유지 가능. 본 컨텍스트에서 새로 생성하는 본문은 무조건 본 규칙 적용.
* gdoc 이관 후에는 markdown bullet 위계가 gdoc 들여쓰기 위계로 변환되므로, md 단계에서 위계가 어긋나면 gdoc 단계에서 수정 비용이 커짐.
