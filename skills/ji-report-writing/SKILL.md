# 제주연구원 보고서 작성 표준

보고서 문장을 쓰기 **전에** 아래 표준 원문을 실제로 읽는다. 요약 기억으로 갈음하지 않는다.
표준을 모르고 쓰면 문체가 통째로 어긋나 전면 재작성하게 된다.

## 표준 원문 (이 플러그인에 같이 들어 있음)

| 무엇 | 파일 | 언제 읽나 |
|---|---|---|
| 톤 | `tone/latest.md` | 본문을 쓰거나 고칠 때 항상 |
| 서식 | `format/latest.md` | 장·절 구조, 표·그림 캡션, md→gdoc→hwpx 흐름 |
| 인용 | `citation/latest.md` | 각주·참고문헌·본문 인용 |

- 경로는 이 플러그인 폴더 기준이다(Claude: `${CLAUDE_PLUGIN_ROOT}/tone/latest.md`).
  스킬 폴더 기준으로는 `../../tone/latest.md` 이다.
- 파일을 찾을 수 없으면 공개 원문을 받는다:
  `https://raw.githubusercontent.com/jeju-inst/ji-writing-standards/main/tone/latest.md`
  (`format/latest.md`, `citation/latest.md` 도 같은 패턴)

## 자주 틀리는 것 (색인일 뿐, 판단 근거는 원문)

- 종결은 **음슴체**("검토함", "전망됨")이고 마침표를 찍지 않는다. 다체·합쇼체 금지.
- **평문 단락 금지.** 본문은 헤딩 아니면 `*` bullet이고, bullet은 **2단까지**, 전부 **문장형**이다.
- 발주처에 내는 권고 문서 톤으로 단정을 완화한다("왜곡이 발생함" → "고평가될 소지가 있음").
- 기간·범위는 전각 물결 `〜`(U+301C). 단 md→Google Docs 변환 경로에서는 하이픈 `-`.

## 작업 방식

1. 사용자가 준 글의 용도(본보고서/JI-Report/대외 공문)를 확인하고 해당 원문을 읽는다.
2. 고친 글을 내놓고, 바꾼 이유를 규칙 이름으로 짧게 단다(예: "평문 → bullet, 톤 §규칙").
3. 점검만 요청받으면 고치지 말고 위반 목록(위치·규칙·제안)을 표로 준다.
4. 프로젝트에 표준을 복사해 넣지 않는다. 적용한 버전(파일의 작성일)을 명시해 참조한다.
